# 10 · Prototipo Figma

## Estado

Prototipo inicial creado y aprobado como insumo obligatorio antes del desarrollo del MVP.

## Archivo Figma

- Nombre: **ATLAS DataGob · MVP Prototype**
- URL: https://www.figma.com/design/FLjnPMpwKXwPij1sanbaAE

## Principio

ATLAS DataGob seguirá enfoque **Figma-first**.

Ningún flujo funcional debe pasar a desarrollo sin pantalla, criterio de usabilidad y criterio de aceptación asociado.

## Pantallas base creadas

### 01 · Dashboard ejecutivo

Objetivo: visualizar el estado del portafolio, prioridades, decisiones pendientes y MVP gates.

Principios Nielsen:

- Visibilidad del estado del sistema.
- Diseño estético y minimalista.
- Reconocimiento antes que memoria.

### 02 · Nueva solicitud

Objetivo: capturar demanda desde correo, texto libre o formulario guiado.

Principios Nielsen:

- Prevención de errores.
- Ayuda y documentación contextual.
- Correspondencia con lenguaje de negocio.

### 03 · Triage asistido

Objetivo: validar sugerencias del agente sobre dominio, subdominio, owner y completitud.

Principios Nielsen:

- Control y libertad del usuario.
- Consistencia y estándares.
- Reconocimiento antes que memoria.

### 04 · Scoring y priorización

Objetivo: calificar iniciativas con criterios ponderados y justificación trazable.

Principios Nielsen:

- Visibilidad del estado.
- Prevención de errores.
- Ayuda para reconocer y corregir errores.

### 05 · Comité y decisión

Objetivo: registrar recomendación operativa y decisión estratégica formal.

Principios Nielsen:

- Consistencia.
- Control humano.
- Salidas claramente visibles.

### 06 · MVP Gate a producción

Objetivo: evaluar si un MVP puede pasar a producción con criterios de valor, datos, seguridad y operación.

Principios Nielsen:

- Prevención de errores críticos.
- Diseño minimalista.
- Trazabilidad.

### 07 · Prototype Scope & Nielsen Checklist

Objetivo: documentar el alcance del prototipo y reglas mínimas antes de desarrollo.

## Pantallas siguientes requeridas

Antes o durante Sprint 01 se deben completar:

1. Detalle de iniciativa.
2. Configuración de dominios y subdominios.
3. Configuración de pesos de scoring.
4. Vista de auditoría / timeline.
5. Panel de insights del portafolio.
6. Vista de configuración de agentes.

## Componentes visuales base

- Logo ATLAS neutral.
- Fondo blanco.
- Tipografía Inter.
- Azul navy para jerarquía principal.
- Azul acento para acciones y foco.
- Verde para estados positivos o avance.
- Ámbar para condiciones o atención.
- Rojo solo para bloqueo o descarte.
- Cards redondeadas.
- Barras de principio clave.
- Dashboard ejecutivo estilo TED + McKinsey.

## Criterios de aceptación del prototipo

- Cada pantalla debe tener objetivo claro.
- Cada acción crítica debe estar visible.
- Cada recomendación agéntica debe distinguirse de una decisión humana.
- Cada estado debe ser visible.
- Debe existir ruta clara para volver, corregir o reformular.
- No debe depender de marca externa.
- Debe permitir uso en contexto corporativo y portafolio personal.
